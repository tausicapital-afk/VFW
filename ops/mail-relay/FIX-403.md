# Fixing the "did not return JSON (HTTP 403)" relay error

## What's actually wrong

The relay script (`index.php`) is fine and already working on the server —
confirmed live by hitting it directly. The problem is one level up, in Apache:

- `GET https://veeb.co.ke/vfw-relay/index.php` → **405** (PHP runs, responds correctly)
- `POST https://veeb.co.ke/vfw-relay/index.php` → **401** `{"ok":false,"error":"Bad or missing relay token."}` (correct JSON)
- `GET/POST https://veeb.co.ke/vfw-relay/` (the folder URL, no filename — **this is what the app is configured to call**) → **403**, and the body isn't JSON at all, it's the site's Privacy Policy page

Apache doesn't know `index.php` is supposed to be the default file for that
folder, so a request for the bare folder URL finds nothing to serve. Because
`.htaccess` also sets `Options -Indexes` (correctly, to stop the folder
contents — including the token — from being listed), Apache's fallback for
"nothing to serve, and I can't list the folder" is a 403, and this account has
a custom 403 error page configured (the Privacy Policy content), which is why
it doesn't look like a normal Apache error.

## The fix

`ops/mail-relay/.htaccess` in this repo has already been updated to add:

```
DirectoryIndex index.php
```

This tells Apache "when someone requests the folder itself, serve index.php."
That's the only change — `index.php` itself (your token, SMTP password) does
not need to change and should NOT be re-uploaded.

## Steps in cPanel

1. Log in to cPanel → **File Manager**.
2. Navigate to `/home3/veebcoke/public_html/vfw-relay/`.
3. Select the existing `.htaccess` in that folder (enable "Show Hidden Files
   (dotfiles)" in File Manager settings if you don't see it) and either:
   - **Edit in place**: right-click → Edit, and add this line at the very top
     of the file:
     ```
     DirectoryIndex index.php
     ```
     then Save.
   - **Or replace the file**: upload the corrected `ops/mail-relay/.htaccess`
     from this repo, overwriting the one on the server.
4. Confirm permissions are `644` (File Manager → right-click → Permissions).
   Should already be correct if you're editing the existing file in place.
5. **Do not touch `index.php`** on the server — it holds your live
   `RELAY_TOKEN` and `SMTP_PASS`, which only exist there, not in git.

## How to verify it worked

From any machine with `curl` (or ask me to re-run this once you're done):

```bash
curl -i https://veeb.co.ke/vfw-relay/
```

- **Before the fix**: `HTTP/1.1 403 Forbidden`, HTML body (Privacy Policy page).
- **After the fix**: `HTTP/1.1 405 Method Not Allowed`, JSON body:
  ```json
  {"ok":false,"error":"POST a JSON message here."}
  ```

Once that 405/JSON response shows up, go back into the app (Administration →
Configuration → Mail accounts) and hit **Send test** on the relay account row.
It should now succeed instead of showing the "did not return JSON" error.

## If it's still 403 after that

That would mean something *outside* this folder's `.htaccess` is intercepting
the request before it even gets here — e.g. a WAF/Imunify360 rule, or a
higher-level `.htaccess` in `public_html/` with its own rewrite rules that
matches `/vfw-relay/` before reaching this folder. In that case, check:

- cPanel → **Security** → **Imunify360** (or ModSecurity) → any blocked
  requests / audit log entries for `vfw-relay` around the time of a failed
  send.
- The `.htaccess` in `public_html/` itself (one level up) for a `RewriteRule`
  that might be catching all non-file paths and redirecting them — this is
  common on sites built as SPAs, and would explain why an unrelated
  nonexistent path on the domain returns 200 instead of 404.
